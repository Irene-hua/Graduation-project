# 答辩回答：数据导入与查询优化问题说明

老师您好，我在做这个系统的开发和测试时，遇到过一个关于**数据导入和查询结果不稳定**的问题。下面我按“遇到了什么问题、怎么解决、为什么这样解决、最后效果如何”四个部分来说明。

## 1. 遇到了什么问题

一开始我把不同的数据集，比如 `test1.txt` 和 `LiHua-World`，都导入到了同一个 Qdrant collection 里。这样做以后，我发现一个现象：**我刚导入哪个数据集，系统就更容易回答哪个数据集的问题**，而之前已经导入的另一个数据集，回答效果就明显变差。

后来我在查询时还观察到，有些问题会出现：

- `Retrieved chunks: 0`
- `Context length: 0`

这说明检索阶段没有拿到有效上下文，最后模型就只能弱答，甚至随便答，结果就不稳定。

## 2. 我是怎么解决的

我主要做了三方面的优化：

### 第一，给导入和查询都加了 `--collection_name` 参数

这样我可以不改 `config.yaml`，就直接指定当前要用哪个 collection。

比如：

- `encrypted_documents_test1`
- `encrypted_documents_lihua`

这样每个数据集都有自己的 collection，互不干扰。

### 第二，导入时增加了 `--reset_collection`

如果我想重新做一个干净的实验，就可以先清空 collection，再重新导入，避免旧数据污染新实验。

### 第三，优化了路径和日志

我把导入脚本改成了会按项目根目录解析相对路径，并且会把导入的 collection 名称、导入时间、导入文件夹、chunk 数量、向量数等信息记录下来。这样后面排查问题时，可以很清楚地知道某次实验到底导入了什么、查的是哪个 collection。

## 3. 为什么这样解决

因为我发现这个问题本质上不是模型本身的问题，而是**数据组织方式的问题**。

如果把多个数据集混在同一个 collection 里：

1. 检索结果会被别的数据集干扰；
2. 查询结果会随着最近一次导入的数据变化；
3. 实验结果就不稳定，也不利于复现。

所以我最后采用的是**“一个数据集一个 collection”**的方式。这样做的好处是：

- 数据隔离清晰；
- 查询目标明确；
- 实验结果可复现；
- 方便比较不同数据集的效果；
- 也更适合论文答辩和后续实验记录。

## 4. 最后的效果如何

优化之后，效果明显更稳定了：

- 导入时不会再因为路径不对而报错不清楚；
- 不同数据集可以分别存放在不同 collection 中；
- 查询时可以明确指定要查哪一个 collection；
- 检索命中率更稳定了，不会再出现“导入哪个数据集，就偏向哪个数据集”的混乱现象；
- 对于单个数据集的测试，答案准确率也提升了，因为检索上下文更干净了。

## 5. 如果老师继续追问，可以这样补充

这个问题表面上是导入和查询的问题，实际上是**实验数据隔离不够严格**。我后来把它改成了 collection 级别的数据隔离，并且统一了导入、查询和检查流程，这样系统的稳定性和可复现性都明显提高了。

## 可直接口头回答的简短版本

老师，我在测试时遇到的主要问题是数据导入和查询结果不稳定。一开始我把不同数据集都导入到同一个 collection 里，导致系统总是更偏向最近导入的数据集，另一个数据集的查询效果就会变差，甚至有些问题检索不到上下文，出现 `Retrieved chunks: 0` 的情况。

后来我做了三方面优化：第一，给导入和查询都增加了 `--collection_name` 参数，支持不改配置文件直接切换数据集；第二，增加了 `--reset_collection`，方便做干净的重新导入；第三，把路径解析和导入日志也做了增强，方便排查问题。

这样解决的原因是，这个问题本质上不是模型问题，而是数据组织和隔离不够清晰。最后的效果是，不同数据集可以独立存放和查询，结果更稳定，也更方便做实验对比和论文展示。
